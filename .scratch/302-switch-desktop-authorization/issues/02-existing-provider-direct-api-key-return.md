# 02 — 在现有私有化配置中直接更新 API Key

**What to build:** 已配置的私有化供应商可以从 Key 编辑窗口使用同一套浏览器登录和直接返回流程获取新 Key；新 Key 验证成功并由用户确认后替换原 Key，公共版和手动输入流程保持原行为。

**Blocked by:** 01 — 首次配置时直接获取私有化 API Key.

**Status:** ready-for-agent

- [ ] Key 编辑窗口复用首次配置的接入地址、待处理状态、回调解析和验证逻辑，不建立第二套实现。
- [ ] 返回的新 Key 只更新当前编辑状态；用户取消保存时原 Key、地址和供应商配置保持不变。
- [ ] 私有化地址被编辑后，接入页面始终使用编辑后的同一个规范化根地址，回调参数不能改变目标地址。
- [ ] 公共 302.AI 获取 Key 链接、手动私有化 Key、普通自定义接口和配置导入行为保持不变。
- [ ] 错误提示区分页面无法访问、登录或创建失败、用户取消、状态不匹配和 Key 验证失败，不显示敏感值。
- [ ] 回归测试覆盖首次配置、现有配置、取消保存、替换成功、公共版和手动输入。
- [ ] `cargo test`、前端 `test`、类型检查、lint 和生产构建通过；不新增授权服务器、临时凭据存储或完整浏览器自动化。
