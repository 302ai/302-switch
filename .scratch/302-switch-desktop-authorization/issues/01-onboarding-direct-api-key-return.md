# 01 — 首次配置时直接获取私有化 API Key

**What to build:** 首次配置私有化实例时，用户点击“获取 API Key”进入该实例的 302 Switch 接入页面；登录并创建 Key 后直接返回桌面端，Key 自动填入并使用现有逻辑验证，用户确认后再写入所选客户端。

**Blocked by:** 302 Enterprise 01 — 登录后创建并返回 302 Switch API Key.

**Status:** ready-for-agent

- [ ] 私有化 Key 输入步骤增加“获取 API Key”，手动输入继续保留。
- [ ] 点击后生成一次性状态值，并只打开用户当前填写的私有化根地址下的固定接入页面。
- [ ] 自动流程要求 HTTPS；开发环境只允许明确的 localhost HTTP 地址，不提供忽略证书错误的选项。
- [ ] `ccswitch302://auth/callback` 与现有配置导入深链接分开处理，只接受状态值和 API Key。
- [ ] 回调状态值必须匹配当前待处理请求；不匹配、缺少字段、用户取消和应用重启后收到旧回调时不修改配置。
- [ ] 成功后自动填入 Key 并执行现有验证，验证通过前不写入任何客户端配置，最终仍由用户点击现有确认按钮。
- [ ] 深链接、API Key 和状态值不以完整形式写入 Rust 日志、前端日志或错误详情；现有记录完整深链接的日志同步删除。
- [ ] 单元测试覆盖接入地址、回调分流、状态匹配、成功回填、无效回调和现有配置导入回归。
- [ ] `cargo test`、前端相关测试、类型检查和构建通过，并在当前 macOS 环境完成一次私有化端到端检查。
